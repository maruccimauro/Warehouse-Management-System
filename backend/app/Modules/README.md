# Módulos

Monolito modular (ADR-001): un módulo por contexto de dominio, con una base PostgreSQL compartida.

| Módulo | Responsabilidad |
| - | - |
| `Identity` | Usuarios, autenticación, roles y permisos, asignación de depósitos |
| `Warehouse` | Depósitos, zonas y ubicaciones |
| `Catalog` | Productos, categorías, unidades de medida y proveedores |
| `Inventory` | Existencias y libro de movimientos |
| `Procurement` | Órdenes de compra |
| `Receiving` | Recepciones y tareas de ubicación (putaway) |
| `Fulfillment` | Pedidos, reservas, picking, packing y despacho |
| `Stocktaking` | Inventario físico, conteos y ajustes |
| `Reporting` | Reportes y consultas de solo lectura |
| `Audit` | Registro de auditoría |

## Estructura de un módulo

Cada directorio se crea cuando el módulo lo necesita.

```
app/Modules/{Nombre}/
├── {Nombre}ServiceProvider.php   extiende App\Shared\Providers\ModuleServiceProvider
├── Actions/                      casos de uso: una clase por operación de negocio
├── Database/Factories/           factories de los modelos del módulo
├── Database/Migrations/          migraciones del módulo, cargadas por el provider
├── Database/Seeders/             datos de desarrollo idempotentes, llamados desde DatabaseSeeder
├── Exceptions/                   excepciones de dominio con código estable (ADR-010)
├── Http/Controllers/
├── Http/Requests/
├── Models/
├── Policies/                     declaradas en $policies del provider
└── Routes/api.php                registrado bajo /api/v1 con el grupo de middleware api
```

## Migraciones

Reproducen el DDL de `docs/03-architecture/database-design.md`.

| Aspecto | Cómo se escribe | Motivo |
| - | - | - |
| Clave primaria | `$table->id()->generatedAs()` | `id()` solo genera `bigserial`; con `generatedAs()` es `GENERATED BY DEFAULT AS IDENTITY` |
| Fechas y horas | `timestampTz()`; `created_at` y `updated_at` con `useCurrent()` cuando el DDL los declara `NOT NULL DEFAULT now()` | `timestamp()` y `timestamps()` generan `timestamp without time zone`. La precisión de microsegundos la fija `AppServiceProvider` |
| Cantidades | `bigInteger()` en unidad base (ADR-005) | Aritmética entera exacta |
| Lo que el Schema Builder no expresa | `DB::statement` en la misma migración: `CHECK`, índices parciales, `NULLS NOT DISTINCT`, claves foráneas compuestas, columnas generadas, triggers | El DDL es la referencia |
| Nombres de restricciones | `{tabla}_{columnas}_{tipo}` | `DatabaseErrorTranslator` traduce por nombre |

`tests/Feature/Database/SchemaConventionsTest.php` recorre el esquema migrado y falla ante una columna `timestamp without time zone`, una precisión distinta de microsegundos o una secuencia `serial`. Las tablas de infraestructura de Laravel (`sessions`, `cache`, `jobs` y afines) quedan como sus migraciones publicadas y se excluyen.

## Alcance por depósito

Todo recurso que pertenece a un depósito respeta REG-005 con `App\Modules\Identity\Authorization\WarehouseAccess` (ADR-009):

- El modelo usa el trait `App\Modules\Warehouse\Models\Concerns\ScopedByWarehouse`, que da los scopes `visibleTo($user)` para listados y `operableBy($user)` para elegir dónde operar. Si la columna no es `warehouse_id`, el modelo redefine `warehouseScopeColumn()`.
- La Policy devuelve `authorizeView()` para consultar y `authorizeOperation()` con el permiso de la acción para operar. El orden es 404 fuera del alcance de consulta, 403 sin operación en el depósito y 403 sin el permiso.

## Reglas

- Solo `Inventory` escribe en `stocks` y `stock_movements`. Los demás módulos invocan sus Actions.
- Un módulo usa otro a través de sus Actions y modelos, nunca de sus controladores.
- Lo transversal que no es de dominio (manejo de errores, controlador de health, provider base) va en `app/Shared`.
- Un módulo nuevo se registra en `bootstrap/providers.php`. `tests/Feature/ModuleRegistrationTest.php` verifica que la lista coincida con ADR-001.
- `tests/Architecture/ModuleBoundariesTest.php` hace cumplir estas reglas con las pruebas de arquitectura de Pest: `Shared` no depende de los módulos, ningún módulo usa la capa HTTP de otro y los modelos de `Inventory` solo se usan en `Inventory` y en `Reporting`.
